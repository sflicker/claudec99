The spec's goal is an `x86_64-macos` target: the same x86-64 NASM code, assembled with `nasm -f macho64`, linked with `clang -arch x86_64` and run under Rosetta 2. The output differs in two ways only:

- C-visible symbols get a `_` prefix.
- The ELF-only `.note.GNU-stack` footer is omitted.

### Ambiguities and spec issues raised

1. **The spec's line table was incomplete.**
   - `emit_load_global`, `emit_store_global`, `emit_load_fp_global` and `emit_store_fp_global` emit `[rel %s]`.
   - They are called with both `gv->name` (needs `_`) and `lv->static_label` (`Lstatic_*`, must not get `_`).
   - The FP-literal global label definitions were also missing from the table.
2. **The spec row for `gv->init_label` was wrong.** `init_label` is either a function name (needs `_`) or an internal `Lstr%d` label from `char *s = "abc"` (must not get `_`).
3. **Auto-detect via `__APPLE__`.** ClaudeC99's own preprocessor predefines `__linux__` and never `__APPLE__`, so a self-hosted ccompiler on macOS defaults to Linux. This was accepted, because `build.sh` always passes `--target`.
4. **The test suites can't run on macOS.** The baseline is 250 passed and 1911 failed: there is no `timeout` command and the runners are ELF-only (Phase 0C). The spec lists no tests, and the self-host phase can't run on this host.

### User decisions

- Item 2: add a flag field, `GlobalVar.init_label_is_internal`.
- Self-host: skip on this host and run later on Linux.

## 4. Verification

- **Linux regression:** all sources were compiled with `--target=x86_64-linux` and diffed against the baseline.
  - Every test `.asm` file is byte-identical to the baseline. The single exception is `test_predefined_macro_time__0`, whose `__TIME__` value changes on every run.
  - The only `src` diffs are in files edited this stage (`codegen`, `compiler`, `version`).
  - The set of files that fail to compile is the same as before.
- **macOS target:** an ad-hoc runner compiled each `test/valid` program with the auto-detected target, assembled it with `nasm -f macho64`, linked it with `clang -arch x86_64` and ran it under Rosetta 2.
  - Result: 1282 passed, 4 failed.
  - All 4 failures are link errors caused by glibc-only names in the `test/include` stubs (out of scope):
    - `_stderr` in `test_assert_fail__134`, `test_assert_pass__0` and `test_stdio_streams__1`
    - `___errno_location` in `test_errno_einval__1`
- **Spec verification script:**
  - `--target=x86_64-macos`: `_main` present, no footer, exit 42 under Rosetta.
  - Auto-detect: same output as `--target=x86_64-macos`.
  - `--target=x86_64-linux`: `main:` plus the footer.
  - `--target=arm64-macos` and an unknown target: error, rc=1.
- **Targeted check:**
  - The output contains `_fp: dq _f`, `_s: dq Lstr0`, `_pa: dq _arr + 4`, `Lstatic_main_2: dq _arr + 8` and `call _puts`.
  - The program returned 43, as expected.
- **Standard suite on macOS:** 250 passed, 1911 failed, the same as the pre-change baseline.
- **Self-host:** deferred to a Linux host.
